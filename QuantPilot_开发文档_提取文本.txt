[[Heading1]] 1. 产品概述与目标
[[Heading2]] 1.1 产品定义
QuantPilot AI 是面向 MT5 交易终端的多账户自动交易与策略管理平台。平台由原生 MQL5 EA 执行端、Windows 本地交易节点、Python 后端服务、AI 分析引擎、传统量化策略引擎、独立风控引擎、Web 管理后台和 Windows 桌面客户端组成。

多账户、多终端、多经纪商环境

QuantPilot AI
[[Heading2]] 1.3 产品目标
[[ListBullet]] 建立稳定的 MT5 交易闭环：行情/信号 → 风控 → EA 执行 → 成交回报 → 对账。
[[ListBullet]] 支持多个独立 MT5 终端和账户，不让一个账户的异常扩散到其他账户。
[[ListBullet]] 让传统策略可插拔、可配置、可回测、可版本化。
[[ListBullet]] 让 AI 负责市场状态理解、策略评分、信号过滤和研究辅助，而不是无约束地产生订单。
[[ListBullet]] 让风控规则独立于 AI 和策略，拥有最终拒绝交易权。
[[ListBullet]] 提供可审计的订单生命周期、账户状态、策略表现和系统事件。
[[ListBullet]] 预留用户、授权、订阅、设备和版本管理能力。
[[Heading2]] 1.4 非目标与明确排除项
[[ListBullet]] 不承诺盈利、胜率或固定回报；不把回测结果描述为未来表现保证。
[[ListBullet]] 首版不开发高频交易基础设施，不承诺微秒级延迟。
[[ListBullet]] 首版不开发面向公众的跟单资金池、代客理财、托管或资金归集业务。
[[ListBullet]] 不允许 LLM 直接持有券商密码或绕过 EA/风控下单。
[[ListBullet]] 不把 AI 模型、网络连接或云服务设为 EA 执行安全的唯一依赖。
[[ListBullet]] 不在第一版开发策略商城、第三方策略市场和自动自我修改实盘策略。
[[Heading2]] 1.5 核心产品原则
原则
工程要求
执行权唯一
正式实盘订单由 MT5 EA 执行；任何辅助接口不得形成第二套隐蔽执行链。
风控优先
风险检查失败、数据过期、账户状态不明时拒绝新增风险。
账户隔离
每个 MT5 终端/账户独立运行上下文、凭据、状态与故障边界。
可审计
信号、风控决定、指令、EA 回执、订单、成交均有可关联 ID。
幂等
网络重试、消息重投、进程重启不得造成重复开仓。
可恢复
重启后从 MT5 实际账户状态重新对账，不盲目重放开仓命令。
渐进发布
默认模拟/只读；实盘必须由用户显式开启并经过安全检查。

[[Heading2]] 2.5 关键业务规则
[[ListBullet]] 账户创建后默认状态为 DISABLED 或 OBSERVE_ONLY；不得自动开始实盘交易。
[[ListBullet]] 每个交易账户必须绑定一个 account_id、terminal_id、node_id 和 broker_server 标识。
[[ListBullet]] 同一账户的真实交易指令必须按账户串行化执行；不同账户可以并行。
[[ListBullet]] 同一交易指令的重复投递必须返回原有执行状态，不得再次开仓。
[[ListBullet]] 所有指令都必须设置 expires_at；过期指令不可执行。
[[ListBullet]] 所有策略信号必须带 symbol、timeframe、生成时间、数据时间、策略版本和信号 ID。
[[ListBullet]] AI 输出只作为决策输入；最终交易命令必须由策略编排器生成并通过风控。
[[ListBullet]] 风控配置更新必须记录审计事件，并支持生效时间与版本。
[[ListBullet]] 当账户、行情、品种规格、终端连接状态任一关键数据过期或未知时，禁止新增风险。
[[ListBullet]] 平仓、撤单、止损调整与新开仓应使用不同 command_type 和权限控制。

[[Heading2]] 4.3 进程隔离原则
[[ListBullet]] 每个 MT5 终端独立进程；避免多个账户复用同一个终端上下文造成账户切换或状态错配。
[[ListBullet]] 每个账户拥有独立 account worker 和 command queue；账户内串行，账户间并行。
[[ListBullet]] Agent 负责进程监督、健康检查、协议转发和状态同步；不实现第二套交易策略。
[[ListBullet]] 后台服务无权直接绕过 EA 交易；Python MetaTrader5 API 只用于受控诊断/研究或只读采集，首版禁止成为正式实盘下单路径。
[[Heading2]] 4.4 一致性模型
数据库是配置、策略版本、风险规则、命令意图和审计的权威存储；MT5 终端/券商服务器是实际订单、成交和持仓的权威来源。后台数据库中的 positions/orders 是可重建的投影，不得在对账失败时被当作真实持仓事实。

[[ListBullet]] EA 默认不接受新开仓命令，直到绑定、风控同步和用户授权完成。

[[Heading1]] 9. 独立风控引擎
[[Heading2]] 9.1 风控架构
风控服务是交易许可的最终权威组件。它接收信号和账户快照，输出明确的 ALLOW / REJECT / REDUCE / REVIEW。EA 还必须执行本地硬限制，因此风控采用云端策略级审核 + EA 本地执行级防护的双层结构。
[[Heading2]] 9.2 风控检查顺序
[[ListNumber]] 系统级：全局停止、维护窗口、服务状态、数据时间戳。
[[ListNumber]] 账户级：账户绑定、交易权限、账户状态、日亏损、最大回撤、保证金水平。
[[ListNumber]] 品种级：交易模式、交易时段、点差、报价新鲜度、规格版本。
[[ListNumber]] 组合级：同向敞口、品种相关性、最大持仓数、策略冲突。
[[ListNumber]] 订单级：手数、止损、最大滑点、预估亏损、保证金占用。
[[ListNumber]] 执行级：EA 本地硬限制、订单请求检查和服务器返回码。
[[Heading2]] 9.3 仓位计算
风险金额优先由账户净值或余额乘以风险比例计算；具体采用哪一种基数必须由账户配置明确。止损距离换算为账户货币的损失金额，应优先使用 MT5 的 OrderCalcProfit 或经验证的经纪商计算规则，不应简单假设所有品种的 pip value 一致。
[[CodeBlock]] risk_budget = risk_basis * risk_fraction
[[CodeBlock]] loss_per_lot = abs(
[[CodeBlock]]     OrderCalcProfit(direction, symbol, 1.0, entry_price, stop_price)
[[CodeBlock]] )
[[CodeBlock]] raw_volume = risk_budget / loss_per_lot
[[CodeBlock]] volume = floor_to_step(raw_volume, volume_step)
[[CodeBlock]] volume = min(volume, symbol_volume_max, account_hard_max_volume)
[[CodeBlock]] if volume < symbol_volume_min:
[[CodeBlock]]     REJECT("VOLUME_BELOW_MIN")
实际执行时还必须校验手续费、滑点缓冲、汇率换算、最小止损距离、保证金、volume step 和服务器端规则。若无法可靠计算预估损失，拒绝新增交易。

[[Heading2]] 13.1 API 设计原则
[[ListBullet]] REST API 用于配置、查询、命令创建和管理操作；WebSocket/SSE 用于状态推送。
[[ListBullet]] 所有写操作携带 Idempotency-Key 和 X-Request-ID。
[[ListBullet]] 统一响应 envelope：data、error、request_id、timestamp。
[[ListBullet]] 版本前缀 /api/v1；破坏性变更使用新版本。
[[ListBullet]] 金额、价格和手数在 JSON 中使用 decimal 字符串，避免二进制浮点误差。
[[ListBullet]] 分页使用 cursor 或 limit/offset；大规模事件查询优先 cursor。

系统行为
AI API 超时
AI 输出 UNKNOWN；切换 OFF/ADVISORY；不阻塞 EA

[[Heading2]] 15.2 回测必须控制的偏差
[[ListBullet]] Look-ahead bias：禁止使用信号生成时尚未可知的数据。
[[ListBullet]] Survivorship bias：品种列表和历史数据需考虑退市/不可交易样本的可用性。
[[ListBullet]] Overfitting：参数优化必须分训练、验证、样本外区间。
[[ListBullet]] Data snooping：限制重复试验造成的选择偏差，保留实验记录。
[[ListBullet]] Execution bias：纳入点差、佣金、swap、滑点、延迟、拒单和部分成交假设。
[[ListBullet]] Timezone/session bias：明确服务器时间、UTC、夏令时和交易日切分。

[[Heading2]] 15.4 MT5 与 Python 回测分工
MT5 Strategy Tester 优先用于验证最终 MQL5 EA 的交易行为和经纪商执行模型；Python 用于数据研究、统计分析、模型训练和组合实验。两边必须使用相同的策略定义、参数、时区和成本假设，并对固定测试区间做结果对照。

[[ListBullet]] 单元/集成测试全部通过；不存在未处理的 P0/P1 缺陷。

[[ListBullet]] Demo 运行期间无重复开仓、无无法解释的账户状态差异。

[[Heading2]] 17.2 编码规范
[[ListBullet]] Python：类型标注、Pydantic schema、ruff/black、pytest、mypy/pyright；业务逻辑不得依赖 FastAPI Request 对象。

[[ListBullet]] MQL5：封装交易调用、检查返回码、避免重复代码；每个关键分支写日志码；所有交易路径有模拟测试。
[[ListBullet]] 数据库：使用 Alembic 迁移；禁止手工修改生产 schema；迁移可回滚或有恢复计划。
[[ListBullet]] 提交：小步提交、清晰 commit message；PR 必须关联需求编号和测试结果。
[[ListBullet]] 配置：环境变量/配置文件分层；不把密钥写入代码、日志或 Git。

[[Heading1]] 21. AI 编程代理工作规范
[[Heading2]] 21.1 总规则
AI 编程工具必须以本文件和仓库 docs/ 中的最新版本为准。不得自行重构系统边界、替换核心技术、删除风控或把 Python 交易接口改为实盘执行主路径。遇到规格冲突先提出 ADR（架构决策记录），不得默默猜测。
[[Heading2]] 21.2 开发顺序
[[ListNumber]] 先阅读 PRD、ARCHITECTURE、API_SPEC、EA_PROTOCOL、RISK_SPEC。
[[ListNumber]] 先建立 contracts/schema 和数据库迁移，再实现服务。
[[ListNumber]] 先实现只读终端发现和账户绑定，再实现模拟交易。
[[ListNumber]] 先完成 command idempotency 和 UNKNOWN 对账，再开放真实订单路径。
[[ListNumber]] 先完成基础风控，再开发策略和 AI 过滤。
[[ListNumber]] 先实现单账户，再实现多账户并行。
[[ListNumber]] 先 Demo 测试，再小风险实盘候选；实盘功能必须显式开关。
[[ListNumber]] 每次只实现一个可验收的垂直切片，避免一次生成整个仓库。
[[Heading2]] 21.3 AI 代理禁止事项
[[ListBullet]] 禁止把 API key、券商密码、token、私钥写入代码或提交到 Git。
[[ListBullet]] 禁止默认开启实盘交易、默认启用自动开仓或默认设置非零风险。
[[ListBullet]] 禁止 AI/LLM 直接调用下单函数或修改风控硬上限。
[[ListBullet]] 禁止在网络超时后盲目重发开仓命令。
[[ListBullet]] 禁止仅凭 OrderSend 布尔返回值判定成交。
[[ListBullet]] 禁止将价格/金额/手数用 float 作为数据库精确金额类型。
[[ListBullet]] 禁止跳过数据库迁移、schema 验证、日志和测试。
[[ListBullet]] 禁止虚构 MT5 API、枚举、品种属性或经纪商能力；必须核对官方文档。
[[ListBullet]] 禁止将回测利润或胜率作为系统验收唯一标准。
[[ListBullet]] 禁止未经用户批准连接真实券商账户或进行真实交易。
